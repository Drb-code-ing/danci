# H5 英语单词学习项目技术设计文档

## 1. 文档目的

本文档用于指导 H5 英语单词学习项目的前后端实现，内容包括：

- 现有数据库表结构和访问约定。
- 用户学习进度相关数据表设计。
- Drizzle ORM schema 设计。
- Next.js App Router 页面与组件结构。
- 登录认证、权限控制和数据流。
- 单词书、单词学习、单词详情和学习进度接口。
- 事务、并发、异常状态和验收要求。

需求依据：

- `docs/proposal.md`
- 当前项目的 Next.js 14、React 18、NextAuth v5 beta、Drizzle ORM 和 `postgres` 配置。

本项目复用已有的 `books`、`words` 表，不修改这两张表的既有字段定义。用户认证沿用项目当前的 Credentials 登录模式，学习进度新增独立数据表。

## 2. 技术栈与分层

### 2.1 技术栈

| 层级 | 技术 |
| --- | --- |
| 前端框架 | Next.js 14 App Router |
| UI | React、Tailwind CSS、shadcn/ui、Radix UI |
| 服务端认证 | NextAuth/Auth.js Credentials |
| ORM | Drizzle ORM |
| 数据库驱动 | `postgres` |
| 数据库 | Supabase PostgreSQL |
| 密码哈希 | `bcrypt-ts` |
| 语言 | TypeScript |

### 2.2 分层原则

```text
页面组件
  ↓
Server Actions / Route Handlers
  ↓
领域查询和写入函数
  ↓
Drizzle schema + 数据库
```

- 页面组件只负责展示、交互和路由跳转。
- 服务端函数负责读取当前会话、校验输入和组织业务流程。
- 数据库访问集中在服务端模块，客户端不得直接连接数据库。
- 学习进度写入必须使用当前会话中的用户 ID。
- 不从客户端请求体中接收可信的 `userId`。

## 3. 数据库连接与现有表

### 3.1 连接配置

使用环境变量 `POSTGRES_URL` 连接 Supabase PostgreSQL：

```ts
import postgres from 'postgres';
import { drizzle } from 'drizzle-orm/postgres-js';

const client = postgres(`${process.env.POSTGRES_URL}?sslmode=require`);
export const db = drizzle(client);
```

数据库连接只允许在服务端模块中初始化。需要避免在客户端组件中导入数据库模块。

### 3.2 现有 `words` 表

数据库定义如下，字段名中的大小写必须通过 Drizzle 显式映射：

```sql
create table public.words (
  id bigint generated by default as identity not null,
  "wordRank" integer null,
  "headWord" text null,
  content json null,
  "bookId" text null,
  constraint words_pkey primary key (id)
) TABLESPACE pg_default;
```

Drizzle schema：

```ts
import { bigint, integer, json, pgTable, text } from 'drizzle-orm/pg-core';

export const words = pgTable('words', {
  id: bigint('id', { mode: 'number' }).primaryKey().generatedByDefaultAsIdentity(),
  wordRank: integer('wordRank'),
  headWord: text('headWord'),
  content: json('content'),
  bookId: text('bookId'),
});
```

字段用途：

- `id`：数据库主键，用于详情页和进度记录。
- `wordRank`：单词在单词书中的顺序，查询时升序排序。
- `headWord`：单词简要展示文本。
- `content`：单词完整 JSON 数据。
- `bookId`：逻辑关联到 `books.book_id`。

由于 `words.bookId` 当前没有数据库外键约束，应用层必须保证查询时使用同一 `bookId` 值。后续如果数据清洗完成，可以补充外键约束，但不作为本期必需改动。

### 3.3 现有 `books` 表

数据库定义如下：

```sql
create table public.books (
  id uuid not null default gen_random_uuid (),
  book_id text not null,
  title text not null,
  word_count integer not null default 0,
  cover_url text null,
  tags text[] not null default '{}'::text[],
  created_at timestamp with time zone not null default now(),
  updated_at timestamp with time zone not null default now(),
  constraint books_pkey primary key (id),
  constraint books_book_id_unique unique (book_id)
) TABLESPACE pg_default;
```

Drizzle schema：

```ts
import {
  integer,
  pgTable,
  text,
  timestamp,
  uuid,
  unique,
} from 'drizzle-orm/pg-core';

export const books = pgTable(
  'books',
  {
    id: uuid('id').defaultRandom().primaryKey(),
    bookId: text('book_id').notNull(),
    title: text('title').notNull(),
    wordCount: integer('word_count').notNull().default(0),
    coverUrl: text('cover_url'),
    tags: text('tags').array().notNull().default([]),
    createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
    updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
  },
  (table) => ({
    bookIdUnique: unique('books_book_id_unique').on(table.bookId),
  }),
);
```

说明：

- `books.id` 是内部 UUID 主键。
- `books.book_id` 是业务单词书 ID，与 `words.bookId` 关联。
- 业务查询统一使用 `book_id`，不能将 `books.id` 与 `words.bookId` 混用。
- `word_count` 是单词书展示和进度分母。必要时可与实际单词数量进行校验。

## 4. 新增学习进度表设计

### 4.1 设计目标

每个用户针对每本单词书保存一条进度记录，用于：

- 首页展示最近学习单词书。
- 我的页面展示学习进度。
- 用户再次进入单词书时从上次学习位置继续。
- 判断单词书是否已经完成。
- 支持完成后重新学习。

### 4.2 推荐表结构

表名使用小写下划线形式：`user_learning_progress`。

```sql
create table public.user_learning_progress (
  id uuid not null default gen_random_uuid(),
  user_id integer not null,
  book_id text not null,
  current_word_id bigint null,
  learned_count integer not null default 0,
  completed boolean not null default false,
  last_studied_at timestamp with time zone null,
  created_at timestamp with time zone not null default now(),
  updated_at timestamp with time zone not null default now(),
  constraint user_learning_progress_pkey primary key (id),
  constraint user_learning_progress_user_book_unique unique (user_id, book_id)
);

create index user_learning_progress_user_recent_idx
  on public.user_learning_progress (user_id, last_studied_at desc);

create index user_learning_progress_book_idx
  on public.user_learning_progress (book_id);
```

### 4.3 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | uuid | 进度记录主键 |
| `user_id` | integer | 当前登录用户 ID，关联项目现有用户表 |
| `book_id` | text | 业务单词书 ID，对应 `books.book_id` |
| `current_word_id` | bigint | 最近一次完成学习的单词 ID；首次学习时为空 |
| `learned_count` | integer | 已完成学习的单词数量 |
| `completed` | boolean | 是否已经完成整本单词书 |
| `last_studied_at` | timestamptz | 最近一次点击“下一个”的时间 |
| `created_at` | timestamptz | 记录创建时间 |
| `updated_at` | timestamptz | 记录更新时间 |

`current_word_id` 的语义必须固定为“最近一次已完成的单词”，而不是当前正在展示但尚未点击“下一个”的单词。这样可以保证恢复学习时直接查询它在当前单词书中的下一个 `wordRank`。

### 4.4 外键策略

建议增加以下外键：

```sql
alter table public.user_learning_progress
  add constraint user_learning_progress_book_fk
  foreign key (book_id) references public.books (book_id)
  on update cascade on delete cascade;
```

`user_id` 是否添加外键取决于当前认证用户表的实际名称和主键类型。由于当前 starter 使用动态创建的 `"User"` 表，实施时必须先确认其最终 schema，再执行对应外键迁移。

如果项目认证用户表最终不使用整数主键，应将 `user_id` 的类型调整为与认证表主键完全一致，不能依靠隐式类型转换。

### 4.5 Drizzle schema

```ts
import {
  bigint,
  boolean,
  integer,
  pgTable,
  text,
  timestamp,
  uuid,
  unique,
  index,
} from 'drizzle-orm/pg-core';

export const userLearningProgress = pgTable(
  'user_learning_progress',
  {
    id: uuid('id').defaultRandom().primaryKey(),
    userId: integer('user_id').notNull(),
    bookId: text('book_id').notNull(),
    currentWordId: bigint('current_word_id', { mode: 'number' }),
    learnedCount: integer('learned_count').notNull().default(0),
    completed: boolean('completed').notNull().default(false),
    lastStudiedAt: timestamp('last_studied_at', { withTimezone: true }),
    createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
    updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
  },
  (table) => ({
    userBookUnique: unique('user_learning_progress_user_book_unique').on(
      table.userId,
      table.bookId,
    ),
    userRecentIndex: index('user_learning_progress_user_recent_idx').on(
      table.userId,
      table.lastStudiedAt,
    ),
    bookIndex: index('user_learning_progress_book_idx').on(table.bookId),
  }),
);
```

如果实际用户表主键不是 integer，只修改 `userId` 的 Drizzle 类型和迁移类型，其他字段保持不变。

## 5. 学习进度业务规则

### 5.1 首次学习

1. 根据 `bookId` 查询单词书和按 `wordRank` 升序排列的单词。
2. 查询当前用户该单词书的进度记录。
3. 没有记录时从排序后的第一个单词开始。
4. 第一次点击“下一个”时创建进度记录：
   - `current_word_id` 写入当前单词 ID。
   - `learned_count` 写入 `1`。
   - `completed` 写入 `false`，除非该书只有一个单词。
   - 写入 `last_studied_at` 和 `updated_at`。

### 5.2 继续学习

1. 读取进度记录中的 `current_word_id`。
2. 查询同一 `bookId` 下 `wordRank` 大于当前单词的第一个单词。
3. 有下一个单词时展示该单词。
4. 没有下一个单词时进入学习完成页。

### 5.3 已完成学习

- `completed = true` 时，进入学习页应直接显示完成状态或完成页。
- 点击“重新学习”时将以下字段重置：
  - `current_word_id = null`
  - `learned_count = 0`
  - `completed = false`
  - `last_studied_at = now()`
  - `updated_at = now()`
- 重置后下一次进入从第一个单词开始。

### 5.4 幂等和并发

进度更新必须以 `(user_id, book_id)` 唯一约束为基础使用 upsert。服务端更新时应重新读取当前单词和单词书关系，不能只相信客户端传入的计数。

推荐更新流程：

1. 校验用户会话。
2. 查询当前单词，确认其属于请求中的 `bookId`。
3. 查询该单词书的总单词数和下一个单词。
4. 在事务中执行 upsert。
5. `learned_count` 使用数据库中的当前值与目标 rank 计算，避免重复点击造成无限递增。
6. 如果不存在下一个单词，将 `completed` 设置为 `true`。

### 6.2 数据访问函数

建议提供以下服务端函数：

```ts
getBooks(): Promise<Book[]>
getBookByBookId(bookId: string): Promise<Book | null>
getWordsByBookId(bookId: string): Promise<Word[]>
getWordById(bookId: string, wordId: number): Promise<Word | null>
getLatestProgress(userId: UserId): Promise<ProgressWithBook | null>
getUserProgress(userId: UserId): Promise<ProgressWithBook[]>

advanceProgress(userId: UserId, bookId: string, wordId: number): Promise<Progress>

```

要求：

- `getWordById` 必须同时限定 `bookId`，防止跨单词书读取。
- 所有进度查询必须带 `userId` 条件。
- 查询函数返回页面所需的最小字段，避免把数据库连接或内部敏感字段传给客户端。
- `content` 作为 JSON 返回时，在服务端或共享类型中定义结构边界。

## 7. API 设计

### 7.1 获取单词书列表

```http
GET /api/books
```

响应：

```json
{
  "data": [
    {
      "bookId": "PEPXiaoXue3_1",
      "title": "小学英语三年级",
      "wordCount": 500,
      "coverUrl": "https://example.com/cover.png",
      "tags": ["小学", "三年级"]
    }
  ]
}
```

该接口允许未登录访问。

### 7.2 获取单词书详情和单词列表

```http
GET /api/books/{bookId}
GET /api/books/{bookId}/words
```

要求：

- `bookId` 使用 `books.book_id`。
- 单词列表按 `wordRank ASC, id ASC` 排序。
- 返回不存在的单词书时使用 404。
- 单词列表响应可只返回学习页必要字段；详情接口再返回完整 `content`。

### 7.3 获取当前用户学习进度

```http
GET /api/learning-progress
GET /api/learning-progress/{bookId}
```

响应示例：

```json
{
  "data": {
    "bookId": "PEPXiaoXue3_1",
    "currentWordId": 120,
    "learnedCount": 120,
    "wordCount": 500,
    "completed": false,
    "lastStudiedAt": "2026-08-27T10:00:00.000Z"
  }
}
```

- 必须从服务端会话中获取用户 ID。
- 未登录返回 401。
- 查询全部进度时按 `last_studied_at DESC` 排序。

### 7.4 推进学习进度

```http
POST /api/learning-progress/{bookId}/next
```

请求体：

```json
{
  "wordId": 120
}
```

服务端处理：

1. 验证会话。
2. 验证 `wordId` 属于 `bookId`。
3. 查询该单词书中是否存在下一个单词。
4. 使用 upsert 创建或更新进度。
5. 返回更新后的进度和完成状态。

响应示例：

```json
{
  "data": {
    "currentWordId": 120,
    "nextWordId": 121,
    "learnedCount": 120,
    "completed": false
  }
}
```

最后一个单词响应：

```json
{
  "data": {
    "currentWordId": 500,
    "nextWordId": null,
    "learnedCount": 500,
    "completed": true
  }
}
```

### 7.5 重置学习进度

```http
POST /api/learning-progress/{bookId}/reset
```

服务端只允许重置当前会话用户自己的进度。不存在进度记录时可以返回初始状态，不创建无必要的记录。

## 8. 认证与权限设计

### 8.1 当前认证模式

项目当前使用：

- NextAuth/Auth.js Credentials provider。
- `getUser(email)` 查询用户。
- `bcrypt-ts` 比较密码哈希。
- `signIn` 创建会话。
- `signOut` 清除会话。

H5 认证弹窗应复用同一套认证服务端逻辑，不额外实现第二套密码验证流程。

### 8.2 登录弹窗流程

```text
首页单词书卡片
    ↓ 未登录
打开 AuthDialog
    ↓
登录 Tab / 注册 Tab
    ↓
Server Action 或认证接口
    ↓
刷新客户端会话状态
    ↓
关闭弹窗并跳转到目标 /books/{bookId}
```

登录成功后需要保存用户原始目标 `bookId`。推荐由客户端组件暂存目标单词书，认证成功后调用 `router.push`，但不得把用户 ID、权限或进度放在客户端作为可信数据。

### 8.3 页面权限

| 资源 | 未登录 | 已登录 |
| --- | --- | --- |
| `/` | 可访问 | 可访问，额外读取最近学习 |
| `/my` | 可访问，显示未登录状态 | 可访问个人信息和个人进度 |
| `/books/[bookId]` | 不可学习 | 可访问 |
| `/books/[bookId]/words/[wordId]` | 不可访问 | 可访问 |
| `GET /api/books` | 可访问 | 可访问 |
| 学习进度 API | 401 | 仅当前用户数据 |

### 8.4 安全边界

- 所有学习进度 API 都调用 `auth()` 获取会话。
- 不接受客户端传入的 `userId` 作为权限依据。
- 查询进度必须使用 `where user_id = session.user.id`。
- 单词详情查询必须同时限定 `bookId` 和 `wordId`。
- 不把密码哈希、数据库连接对象或会话内部字段返回给客户端。
- 数据库错误对客户端返回通用错误信息，详细错误只记录服务端日志。

## 9. 前端页面与组件设计

### 9.1 页面路由

```text
app/
├── page.tsx                              首页
├── my/page.tsx                           我的
├── books/[bookId]/page.tsx               单词学习页
└── books/[bookId]/words/[wordId]/page.tsx 单词详情页
```

学习完成页可以采用独立路由：

```text
/books/[bookId]/complete
```

也可以由学习页根据服务端响应渲染完成状态。本期推荐独立路由，便于刷新、返回和测试。

### 9.2 共享组件

```text
components/
├── mobile-shell.tsx       移动端页面容器
├── bottom-tabs.tsx        底部首页/我的导航
├── book-card.tsx          单词书卡片
├── recent-learning.tsx    最近学习模块
├── auth-dialog.tsx        登录/注册双 Tab 弹窗
├── login-form.tsx         登录表单
├── register-form.tsx      注册表单
├── word-card.tsx          简洁单词卡片
├── word-detail.tsx        单词详情内容
├── progress-bar.tsx       学习进度条
├── progress-list.tsx      我的页面进度列表
└── loading-state.tsx      加载状态
```

### 9.3 首页数据流

服务端首页读取：

1. `getBooks()` 获取全部单词书。
2. 通过 `auth()` 判断是否有会话。
3. 已登录时调用 `getLatestProgress(userId)`。
4. 仅当最近学习记录存在时渲染最近学习模块。
5. 将可序列化的书籍和进度数据传递给客户端交互组件。

点击单词书：

- 未登录：打开 `AuthDialog`。
- 已登录：跳转 `/books/{bookId}`。

### 9.4 我的页面数据流

- 未登录时不查询用户进度，直接渲染登录提示。
- 已登录时查询当前用户邮箱和 `getUserProgress(userId)`。
- 进度列表可以按 `lastStudiedAt DESC` 排序。
- 百分比计算为 `learnedCount / wordCount * 100`，结果限制在 0 到 100 之间。

### 9.5 学习页数据流

推荐使用服务端页面获取单词书和单词基础列表，客户端组件负责当前索引和按钮交互：

```text
服务端读取 book + words + progress
    ↓
计算初始 word index
    ↓
WordStudyClient 渲染卡片
    ↓
点击“下一个”
    ↓
POST /api/learning-progress/{bookId}/next
    ↓
更新本地 index 或跳转完成页
```

初始索引计算：

- 无进度：`0`。
- 未完成且有 `currentWordId`：定位其后的第一个单词。
- 已完成：跳转完成页。
- `currentWordId` 不存在或数据不一致：回退到第一个单词，并记录服务端警告。

### 9.6 单词卡片字段

从 `words.content` 中读取以下字段：

```ts
type WordCardData = {
  id: number;
  wordRank: number | null;
  headWord: string | null;
  content: {
    word?: {
      wordHead?: string;
      content?: {
        usphone?: string;
        ukphone?: string;
        sentence?: {
          sentences?: Array<{
            sContent?: string;
            sCn?: string;
          }>;
        };
      };
    };
  } | null;
};
```

展示优先级：

- 单词：`headWord`，为空时使用 `content.word.wordHead`。
- 音标：优先 `usphone`，为空时使用 `ukphone`。
- 示例句：使用 `sentence.sentences[0]`。
- 缺失示例句时只隐藏示例句区域，不影响单词卡片渲染。

### 9.7 单词详情字段

详情页读取 `content.word.content`：

- `usphone`、`ukphone`：美式和英式音标。
- `trans`：中英文释义。
- `sentence.sentences`：所有例句。
- `syno.synos`：同近词。
- `relWord.rels`：同根词。
- `remMethod.val`：记忆方法。
- `usspeech`、`ukspeech`：音频资源标识。

每个区块先判断数据是否存在，空数组和空字符串不渲染标题或容器。

## 10. 组件交互与状态

### 10.1 AuthDialog

状态：

- `open`：弹窗是否打开。
- `tab`：`signin` 或 `signup`。
- `pending`：表单提交中。
- `error`：认证错误信息。

行为：

- 切换 Tab 时清理当前错误信息。
- 提交期间禁用表单按钮，防止重复请求。
- 登录成功后刷新 session，再执行目标路由跳转。
- 关闭弹窗时清理表单错误和 pending 状态。

### 10.2 WordStudyClient

状态：

- 当前单词索引。
- 当前单词数据。
- 是否正在提交进度。
- 进度保存错误。
- 是否已完成。

按钮行为：

- “下一个”提交当前 `wordId`。
- 请求成功且有下一个单词时更新索引。
- 返回 `completed = true` 时跳转完成页。
- 请求失败时保持当前单词，显示可重试提示。

### 10.3 BottomTabs

- 当前路径为 `/` 时选中首页。
- 当前路径为 `/my` 时选中我的。
- 学习页和详情页可以保留底部导航，也可以通过页面返回按钮返回主 Tab；项目实现时保持全局布局一致。
- 内容区域使用底部 padding，避免被固定导航覆盖。

## 11. 错误处理

### 11.1 HTTP 错误约定

| 状态码 | 场景 |
| --- | --- |
| 400 | 请求参数缺失或格式错误 |
| 401 | 没有登录或会话失效 |
| 404 | 单词书或单词不存在 |
| 409 | 资源状态冲突 |
| 500 | 服务端或数据库异常 |

### 11.2 前端处理

- 401：打开登录弹窗或跳转到首页。
- 404：展示“内容不存在”并提供返回首页入口。
- 500：展示通用错误提示和重试入口。
- 学习进度写入失败：不改变当前卡片，允许用户重试。
- 单词书为空：展示空状态，不渲染空卡片列表。
- 单词书没有单词：展示“暂无单词数据”，不进入学习卡片流程。

### 11.3 数据一致性

- 进度提交必须验证单词属于目标单词书。
- `learned_count` 不得小于 0，不得大于单词书总数。
- 完成状态只能在最后一个有效单词推进后设置。
- 重新学习和推进学习均使用数据库事务。
- 删除单词书时，如果启用外键级联，应同时删除对应进度；否则删除单词书前显式删除进度记录。

## 15. 技术决策总结

- `books.book_id` 是单词书业务主键，`words.bookId` 与其关联。
- `words.id` 是单词进度和详情查询使用的数据库主键。
- `current_word_id` 表示最近一次已经完成的单词，不表示正在浏览的单词。
- 用户和单词书通过 `user_id + book_id` 唯一约束保证一书一条进度。
- 所有进度读写都必须在服务端根据会话确定用户身份。
- 单词卡片保持最小信息，完整数据在单词详情页分区渲染。
- 认证复用现有 NextAuth Credentials 逻辑，H5 只改变交互承载方式，不复制认证实现。
