# H5 英语单词学习项目需求文档

## 1. 项目概述

### 1.1 项目名称

H5 英语单词学习项目。

### 1.2 项目目标

为用户提供一个适合移动端使用的英语单词学习工具。用户可以浏览单词书、查看单词卡片、进入单词详情、继续上次的学习进度，并在“我的”页面查看账号信息和各单词书的学习进度。

### 1.3 使用场景

- 用户在手机浏览器中打开 H5 页面。
- 未登录用户可以浏览全部单词书。
- 登录用户可以继续学习最近使用的单词书。
- 用户可以通过简洁的单词卡片快速学习，并按需查看完整释义和扩展内容。

## 2. 已确认的产品决策

- 单词书和单词数据复用当前项目已有的 `books`、`words` 表。
- 学习进度保存在数据库中，按用户和单词书维度保存。
- 未登录用户点击单词书后，使用一个包含“登录”和“注册”两个 Tab 的弹窗完成认证。
- 用户完成一本单词书后进入学习完成页。
- 认证表单和服务端认证逻辑参考现有页面：
  - `app/login/page.tsx`
  - `app/register/page.tsx`
- 本期只面向 H5 移动端体验设计，但页面应具备基本的响应式能力。

## 3. 页面与路由

| 路由 | 页面 | 登录要求 |
| --- | --- | --- |
| `/` | 首页，单词书列表和最近学习 | 否 |
| `/my` | 我的，账号信息和学习进度 | 否，登录后展示完整内容 |
| `/books/[bookId]` | 单词学习页 | 是 |
| `/books/[bookId]/words/[wordId]` | 单词详情页 | 是 |

认证弹窗不作为独立业务页面，但可以复用现有登录和注册页面中的服务端认证逻辑。

## 4. 全局布局与导航

### 4.1 底部 Tab

所有主要 H5 页面使用固定底部导航，包含两个 Tab：

- 首页：点击进入 `/`。
- 我的：点击进入 `/my`。

底部导航需要：

- 固定在视口底部。
- 避免遮挡页面内容。
- 适配移动端底部安全区域。
- 清晰显示当前选中的 Tab。
- 使用图标和文字组合表达导航含义。

### 4.2 页面内容区域

- 页面内容区域需要预留底部导航高度和安全区域。
- 页面整体使用移动端单列布局。
- 单词书列表、学习进度和详情内容均应支持长页面滚动。
- 页面加载、空数据、错误和未登录状态需要分别处理。

## 5. 首页需求

### 5.1 未登录状态

未登录用户进入首页时：

- 不展示“最近学习”模块。
- 展示全部单词书列表。
- 用户可以浏览单词书的封面、标题、单词数量和 `bookId`。
- 用户点击单词书后，不直接进入学习页，而是打开登录/注册弹窗。
- 弹窗认证成功后，关闭弹窗并进入用户刚才点击的单词书学习页。

### 5.2 已登录状态

已登录用户进入首页时：

- 如果用户存在学习记录，展示“最近学习”模块。
- “最近学习”展示最近学习的单词书、当前进度和继续学习入口。
- 点击“继续学习”进入对应单词书的学习页。
- 如果用户没有任何学习记录，不展示“最近学习”模块。
- “最近学习”下方展示全部单词书列表。

### 5.3 单词书卡片

单词书卡片至少展示：

- 封面：使用 `coverUrl`，无封面时使用统一占位样式。
- 标题。
- 单词数量。
- `bookId`。
- 已登录用户可额外展示当前学习进度。

单词书卡片是可点击区域，点击后执行登录判断或进入学习页。

## 6. 登录与注册弹窗

### 6.1 触发条件

未登录用户点击任意单词书时打开认证弹窗。

### 6.2 弹窗结构

弹窗顶部使用两个 Tab：

- 登录。
- 注册。

登录表单字段：

- 邮箱。
- 密码。
- 登录按钮。

注册表单字段：

- 邮箱。
- 密码。
- 确认密码。
- 注册按钮。

### 6.3 认证行为

- 登录成功后保存会话状态，关闭弹窗并进入原目标单词书。
- 注册成功后按现有认证逻辑处理，注册完成后进入登录状态或引导用户登录。
- 邮箱、密码和确认密码需要进行必要的表单校验。
- 认证失败时在弹窗内显示错误信息，不跳转到无关页面。
- 用户可以点击关闭按钮取消认证并返回首页。
- 认证实现复用现有 `app/login/page.tsx` 和 `app/register/page.tsx` 中的 `signIn`、`createUser`、`getUser` 等逻辑模式。

- 展示未登录提示。
- 展示登录按钮。
- 点击登录按钮打开登录/注册双 Tab 弹窗。

- 退出成功后刷新页面状态并回到未登录的“我的”页面。

## 8. 单词学习页需求

### 8.1 进入学习页

用户进入 `/books/[bookId]` 时：

- 页面根据 `bookId` 查询对应单词书和单词列表。
- 单词按照 `wordRank` 升序排列。
- 用户必须处于登录状态。
- 未登录用户访问学习页时，跳转首页并打开认证弹窗，或根据现有路由守卫统一处理。

### 8.2 开始位置规则

- 用户没有该单词书的学习记录时，从第一个单词开始。
- 用户存在未完成的学习记录时，从最近一次记录单词的下一个单词开始。
- 用户已完成该单词书时，进入完成状态或由用户选择重新学习。
- 如果最近记录已经是最后一个单词，则进入学习完成页。

### 8.3 单词卡片

单词学习页使用简单的卡片展示单词，不在卡片中一次性展示所有详情。

卡片展示字段：

- 单词：`headWord`，缺失时使用 `content.word.wordHead`。
- 音标：优先展示 `content.word.content.usphone`，没有时展示 `ukphone`。
- 一个示例句：使用 `content.word.content.sentence.sentences[0]`。
- 英文例句：`sContent`。
- 中文例句：`sCn`。

交互：

- 点击单词名称或卡片主要内容进入单词详情页。
- 点击“下一个”切换到下一个单词。
- 点击“返回”返回首页或上一页。
- 切换单词后保存学习进度。
- 页面顶部展示当前学习数量和总数量。

### 8.4 进度保存规则

用户点击“下一个”后：

- 将当前学习位置写入数据库。
- 更新该用户该单词书的已学数量。
- 更新 `lastStudiedAt`。
- 最后一个单词完成后将 `completed` 标记为 `true`。
- 进度保存失败时保留当前页面交互，并显示错误提示，避免静默丢失状态。

## 9. 单词详情页需求

### 9.1 页面目标

详情页用于展示单词的完整学习数据。页面不要求一次展示所有字段，应根据数据存在情况分区展示。

### 9.2 数据渲染

详情页主要读取单词的 `content.word.content` 字段：

- 基础信息：`wordHead`、`wordId`。
- 音标：`usphone`、`ukphone`。
- 例句：`sentence.sentences`，展示 `sContent` 和 `sCn`。
- 同近词：`syno.synos`，展示词性、释义和关联单词。
- 同根词：`relWord.rels`，按词性展示 `hwd` 和 `tran`。
- 记忆方法：`remMethod.val`。
- 中英文释义：`trans`，展示 `tranCn`、`tranOther` 和必要的说明字段。
- 发音资源：`usspeech`、`ukspeech`，如项目提供音频播放能力则展示播放入口。

缺少某个字段时不展示空区块。

## 11. 数据设计

### 11.1 复用现有数据表

#### `books`

使用现有单词书表，至少需要提供：

- 单词书标题。
- 单词数量。
- 封面 URL。
- `bookId`。
- 标签或其他已有展示字段。

#### `words`

使用现有单词表，至少需要提供：

- `wordRank`。
- `headWord`。
- `content`。
- `bookId`。

`words.bookId` 与 `books.bookId` 关联，用于查询单词书下的全部单词。

### 11.2 新增学习进度表

建议新增 `user_learning_progress` 表：

```text
user_learning_progress
├── id
├── user_id
├── book_id
├── current_word_id
├── learned_count
├── completed
├── last_studied_at
├── created_at
└── updated_at
```

字段要求：

| 字段 | 说明 |
| --- | --- |
| `id` | 进度记录唯一 ID |
| `user_id` | 当前用户 ID，关联现有用户表 |
| `book_id` | 单词书 ID 或 `bookId` |
| `current_word_id` | 最近一次学习的单词 ID |
| `learned_count` | 已学习单词数量 |
| `completed` | 是否完成该单词书 |
| `last_studied_at` | 最近学习时间 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

约束和索引：

- 对 `user_id + book_id` 建立唯一约束。
- 对 `user_id + last_studied_at` 建立查询索引，支持获取最近学习记录。
- 对 `book_id` 建立查询索引，支持查询单词书进度。
- 进度表中的用户 ID 必须来自当前登录用户，不能由客户端任意指定。

## 12. 服务端接口需求

接口名称可根据项目现有约定调整，但需要具备以下能力：

### 12.1 单词书接口

- 查询全部单词书。
- 根据 `bookId` 查询单词书详情。
- 根据 `bookId` 查询单词列表。

### 12.2 学习进度接口

- 查询当前用户的全部学习进度。
- 查询当前用户最近学习的单词书。
- 查询当前用户某本单词书的学习进度。
- 创建或更新当前用户某本单词书的学习进度。
- 将某本单词书重置为未开始状态。

### 12.3 权限要求

- 浏览单词书列表可以不登录。
- 学习进度接口必须登录。
- 服务端从会话中获取用户 ID，不能信任请求体中的用户 ID。
- 未登录用户访问学习页和进度接口时返回未授权结果或执行统一跳转。

## 13. 页面状态

每个页面至少需要处理以下状态：

- 加载中：展示稳定的加载占位，避免页面跳动。
- 空数据：首页没有单词书时展示空状态；用户没有学习记录时隐藏最近学习模块。
- 未登录：我的页面显示登录提示，首页允许浏览但进入学习前要求认证。
- 请求失败：展示可理解的错误提示，并提供重试或返回入口。
- 登录失败：错误信息显示在认证弹窗内。
- 学习完成：进入完成页，不继续请求不存在的下一个单词。

## 14. 关键业务流程

### 14.1 未登录用户开始学习

```text
用户打开首页
    ↓
浏览全部单词书
    ↓
点击某本单词书
    ↓
打开登录/注册双 Tab 弹窗
    ↓
完成登录或注册并登录
    ↓
关闭弹窗
    ↓
进入刚才选择的单词书学习页
```

### 14.2 登录用户继续学习

```text
用户打开首页
    ↓
读取当前用户最近学习记录
    ↓
展示最近学习单词书
    ↓
点击继续学习
    ↓
读取该书进度
    ↓
从最近学习单词的下一个单词开始
```

### 14.3 单词学习完成

```text
进入最后一个单词
    ↓
点击“下一个”
    ↓
保存完成状态
    ↓
进入学习完成页
    ├── 返回首页
    └── 重新学习，从第一个单词开始
```

## 15. 非功能要求

### 15.1 移动端体验

- 以 375px 宽度作为基础设计参考。
- 适配常见手机屏幕宽度。
- 点击区域应适合触摸操作。
- 固定底部导航不能覆盖按钮和内容。
- 长文本和英文释义需要自动换行。

### 15.2 视觉要求

- 使用现有项目的 Tailwind CSS 和 shadcn/ui 组件风格。
- 学习卡片保持简洁，突出当前单词和一个示例。
- 详情页按信息类型分组，保证内容易读。
- 登录/注册使用 shadcn 弹窗组件，不使用浏览器原生弹窗。
- 不在首页使用与实际功能无关的营销区块。

### 15.3 安全要求

- 密码不能以明文保存。
- 会话由服务端认证系统管理。
- 所有学习进度写入操作都必须校验当前登录用户。
- 不能通过修改 URL 中的用户信息读取其他用户进度。

## 16. 验收标准

### 首页

- 未登录用户能查看全部单词书。
- 未登录用户点击单词书会弹出登录/注册双 Tab 弹窗。
- 登录用户有学习记录时能看到最近学习模块。
- 登录用户无学习记录时不显示最近学习模块。
- 首页底部存在首页和我的两个 Tab。

### 认证

- 用户可以在弹窗中完成登录。
- 用户可以在弹窗中完成注册。
- 登录失败时弹窗显示错误信息。
- 登录成功后进入原来点击的单词书。
- 我的页面可以退出登录。

### 学习页

- 单词按 `wordRank` 升序显示。
- 卡片只展示单词、音标和一个例句。
- 点击单词可以进入详情页。
- 点击下一个可以切换单词并保存进度。
- 有历史进度时从下一个单词继续。
- 最后一个单词之后进入完成页。

### 详情页

- 能展示单词、音标、释义和例句。
- 有数据时展示同近词、同根词和记忆方法。
- 缺少字段时不渲染空区块。
- 长文本能够正常换行，不遮挡其他内容。

### 我的页面

- 登录后显示用户邮箱。
- 登录后显示已有学习进度。
- 展示已学数量、总数量、百分比和完成状态。
- 退出登录后回到未登录状态。

### 数据与权限

- 单词书和单词数据来自现有 `books`、`words` 表。
- 每个用户每本单词书只有一条学习进度记录。
- 未登录用户不能写入学习进度。
- 用户不能读取其他用户的学习进度。
